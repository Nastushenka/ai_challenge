# Nastia Chat — веб-интерфейс DeepSeek

Сторонние библиотеки не нужны.

```bash
cd web-simple
cp .env.example .env
# Впишите ключ в LLM_API_KEY внутри .env
python3 server.py
```

Откройте в браузере: <http://127.0.0.1:8000>

По умолчанию используется `deepseek-v4-pro` через официальный Responses API
DeepSeek. Адрес API и модель настраиваются в локальном файле `.env`:

- `LLM_API_KEY` — API-ключ;
- `LLM_BASE_URL` — `https://api.deepseek.com`;
- `LLM_MODEL` — `deepseek-v4-pro`.

Файл `.env` исключён из Git и не попадёт в репозиторий.

## Temperature

Флаг `Настроить temperature` включает явную передачу параметра в диапазоне от
`0` до `2`. Пока флаг выключен, параметр не отправляется и модель использует
настройку по умолчанию. При включении приложение переводит модель в non-thinking
режим, потому что DeepSeek игнорирует temperature в thinking mode. Выбранное
значение применяется к обычным запросам, диалогу и всем генерациям режима
сравнения.

Флаг `Сравнить 3 значения temperature` отправляет один и тот же запрос при
`temperature = 0`, `0.7` и `1.2`. Ответы показываются одновременно, после чего
отдельная генерация сравнивает их по точности, креативности и разнообразию. В
итоговом выводе указывается, для каких типов задач лучше подходит каждое значение.
Этот режим нельзя включить одновременно со сравнением четырёх промпт-подходов;
ручная настройка temperature на время сравнения отключается.

## Ограничение длины запроса

Флаг `Ограничить длину запроса` включает пользовательский предел от 1 до 12 000
символов. Рядом с полем запроса отображается живой счётчик. Если текст длиннее
выбранного значения, он не отправляется, а интерфейс показывает ошибку. Сервер
повторно проверяет ограничение во всех режимах, включая оба режима сравнения.
Когда флаг выключен, действует общий технический предел 12 000 символов.

## Сравнение четырёх подходов

Флаг `Сравнить 4 подхода к решению` запускает один и тот же запрос четырьмя
способами:

1. Прямой ответ без дополнительных инструкций.
2. Проверяемое пошаговое решение: цель, факты и ограничения, обоснованные шаги,
   проверка альтернатив и отдельный итог.
3. Сначала модель-помощник создаёт самодостаточный промпт с ролью, задачей,
   исходными данными, ограничениями, методом самопроверки и форматом ответа. Затем
   другая генерация решает задачу по созданному промпту.
4. Группа из аналитика, инженера и критика предлагает независимые решения.

После получения всех вариантов модель отдельно сравнивает их корректность,
полноту, понятность и надёжность, выбирает лучший подход и формирует итоговый
вывод. В режиме сравнения настройки формата и завершения временно отключаются,
чтобы прямой ответ не получал скрытых инструкций.

## Формат ответа

Модели передаётся строгая инструкция отвечать на русском языке тремя блоками:

1. `Краткий ответ:` — одно-два предложения.
2. `Основные пункты:` — нумерованный список из двух-пяти пунктов.
3. `Итог:` — одно заключительное предложение.

По умолчанию ответ ограничен 200 словами. В поле «Максимум слов» можно указать
значение от 20 до 2000; ограничение применяется в любом режиме. Сервер проверяет
фактическую длину и обрезает превышение. Формат полностью указан в веб-интерфейсе.
Галочка «Использовать структурированный формат» включает шаблон; если снять
галочку, запрос отправляется без инструкции о структуре ответа.

## Диалог до готового результата

В интерфейсе доступны четыре режима завершения:

- `Обычный ответ` — без дополнительного условия;
- `Явная инструкция` — пользователь задаёт модели правило завершения;
- `Stop sequence` — ответ обрезается на указанном маркере, сам маркер скрывается;
- `Уточнять до готовности` — модель ведёт диалог до выполнения критерия.

Режим `Уточнять до готовности` превращает одиночный запрос в диалог. Пользователь
описывает желаемый результат и критерий готовности. Пока данных не хватает, модель
задаёт по одному уточняющему вопросу. Когда условие выполнено, она возвращает
итоговый результат, а интерфейс показывает статус `Данных достаточно — итог готов`.

Например, для запроса о рецепте модель может уточнить вид салата, ингредиенты и
количество порций, после чего завершить сбор информации и выдать рецепт. История
до 20 сообщений передаётся модели с каждым следующим запросом; новый диалог можно
начать отдельной кнопкой.
